# Real-site hardening pass — 2026-08-03

Third pass. The first two (both 2026-08-02) covered Gmail, Meta Business Suite,
Wikipedia, Hacker News and eBay. This one added **OAuth sign-in, popup windows,
and form-heavy checkout**, and cleared every numbered item in `TODO.md`.

Tests: **62 → 75 Node**, **59 → 68 DOM**. All green.

---

## The bug that mattered most

**A backgrounded tab silently dropped every click and keystroke.**

`Input.dispatchMouseEvent` and `Input.dispatchKeyEvent` land nowhere when
`document.visibilityState === "hidden"`. Nothing errors. The call reports
success, the page never sees it, and the agent carries on believing it clicked.

What made it invisible is that **screenshots and the accessibility tree work
perfectly on hidden tabs**. Everything looks healthy right up until you check
whether the click actually did anything.

Reproduced cleanly: a planted button with a DOM-visible click handler sat at
`UNCLICKED` through two clicks of seven seconds each; activating the tab made
the next one fire in 1.2s. `ensureForeground()` now activates the tab before any
trusted input.

The cost is real and worth stating: **input cannot be parallelised across tabs
in one window**, because only one tab per window is foreground. Reading still
parallelises fully. That is a Chrome constraint, not a design choice, and
serialising input is strictly better than dropping it. `docs/CAPABILITIES.md`
previously oversold this and has been corrected.

## What the new flows established

**OAuth works, and the safety boundary is right.** A real third-party sign-in
drove a cross-origin redirect to `accounts.google.com/v3/signin/accountchooser`
with refs, waits and page headers all tracking it. The blocklist then stopped
automation of the credential page with a usable message. No credentials were
entered and no consent was granted — that is a human's job, by design.

**Popup-based OAuth is covered.** A real `window.open(url, name,
'width=520,height=640')` popup was reported the moment it opened, and the popup
window then read and inspected normally.

**Form mechanics hold.** Five fields filled in one call, every value verified by
reading the DOM rather than trusting the tool's own report, plus a checkbox
whose state change came back correctly in the delta.

## Everything else fixed

| Fix | What it did before |
|---|---|
| Session owns only tabs it opened | Reading your tab claimed it forever, locking out every later session |
| Readable session names | `opencode 8cac` — four characters of hex |
| Tabs cleaned up on disconnect | Agent tabs accumulated indefinitely |
| Recycled MV3 worker reported honestly | Flashed "not connected" every idle cycle on a healthy link |
| A click that opens a new tab is reported | Silent dead end; the result was one tab over |
| `browser_batch` takes its own `tabId` | Every step had to repeat it |
| `wait` sees accessible names | `find` showed a string that `wait` could never match |
| Scoping a read to one element | Returned nothing — reads as "not on the page" |
| `browser_eval`'s `ref` binds `element` | Accepted and ignored outright |
| A click that changed nothing says why | Silence, identical to a click that worked |
| "message channel closed" handled | Raw Chrome internal leaked to the caller |

## The lesson worth carrying

**Three consecutive fixes were themselves wrong, and each passed code review and
its own unit tests.** Every one was caught by the first live click afterwards.

- *Scoping a read to one element.* The first version emitted the scoped
  container too, nesting every scoped read under a wrapper line — a token cost
  on every page. The DOM suite caught it turning a 12-node form read into one.
- *The settling signal.* The first version could never fire. It triggered on "no
  delta at all", and clicking anything focusable always produces a delta,
  because the tree reports `focused` as a state change.
- *The mutation counter behind it.* Polluted by the tool's **own** highlight
  box, which appends and removes a `.ob-highlight` div around every action. A
  button planted to do nothing reported "the page is still changing" — and that
  is the failure direction that sends an agent into a retry loop.

Budget a real-page check per **fix**, not per feature.

## Still open

- **Payment entry — untested on purpose.** Card fields are usually a
  cross-origin iframe, which the frame routing handles in principle. Closing
  this properly means a payment provider's sandbox with test card numbers, never
  real ones.
- **The bfcache fix is unverified.** It extends a tested recovery path to a third
  wording of the same condition, but bfcache storage is opportunistic and the
  timing could not be reproduced across several attempts. Verified by inspection
  only — the one claim in this set without evidence behind it.
- **One unexplained failure.** An add-to-cart click reported success while the
  cart stayed at zero. Not reproducible, and the obvious culprit — the hidden-tab
  bug — does not fit, since that fix was already live during the failing run.
- **Infinite scroll** still unproven; both Reddit attempts hit a bot challenge,
  which the tool correctly refused to bypass.

## Calibration

Sites hardened in earlier passes produced **no** new bugs. Each genuinely new
site shape produced several. Expect that to continue: well-hardened against what
it has been driven against, and roughly one bug per unfamiliar kind of site.

Hard limits, unchanged: bot walls (Cloudflare, Imperva, DataDome — refused by
design), canvas and WebGL apps where the tree returns nothing, and closed shadow
roots.
