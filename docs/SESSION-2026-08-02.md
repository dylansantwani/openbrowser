# Real-site hardening pass — 2026-08-02

Second pass of driving the extension against real sites. The first pass (same
day, earlier) covered Gmail, Meta Business Suite and Wikipedia and found twelve
bugs. This pass added **Hacker News and eBay**, cleared the top of `TODO.md`,
and found nine more.

Commits: `6b17388`, `357ae8b`, `a6a6dcd`, `e069536`.
Tests: **49 → 62 Node**, **48 → 59 DOM**. All green.

---

## The pattern worth remembering

Almost every bug found had the same shape: **the tool reported success, or
silence, for work it had not done.**

Not "cannot drive this site" — the driving worked everywhere. Finding elements,
clicking, typing, navigating and scraping succeeded on all four sites. The
failures were in *reporting*: an ignored argument, a retry that checked the
wrong field, a buffer showing another site's errors, a CAPTCHA warning on a
working page.

When changing this project, the question to ask is not "does this work" but
"what does it say when this silently fails".

## What landed

### Tree caching — the biggest speed win

`buildTree` now memoises on `(mode, selector, viewportOnly + scroll)`.

| Page | Cold | Warm |
|---|---|---|
| Wikipedia (Chicago) | 242ms | 33–46ms |
| Gmail inbox | 180ms | 9–43ms |

Two parts of the invalidation are load-bearing and easy to remove by accident:

**`observer.takeRecords()` is drained synchronously on every read.** The
MutationObserver callback is a microtask, so a caller that mutates the DOM and
reads the tree in the same synchronous stretch would otherwise be handed the
tree from *before* its own change.

**Focus is compared, not listened for.** Chrome updates `document.activeElement`
immediately but withholds `focus`/`focusin` until the document has system focus
— which for a backgrounded tab may be never. Since parallel agent work makes
backgrounded tabs the normal case, a `focusin` listener misses every focus
change that matters. This was found by writing the listener version first and
watching the DOM test fail with the document unfocused.

### Tools that lied

| Fix | What it did before |
|---|---|
| Argument validation | `browser_navigate {newTab:true}` — no such param — was silently dropped, and the call drove whatever tab was active |
| `browser_eval` multi-statement | Retry tested `exceptionDetails.text`, which is only ever `"Uncaught"`; the real message is on `exception.description`, so the retry never fired |
| Console/network buffers | Keyed by tab and cleared only on close, so Hacker News returned `mail.google.com` CORS errors |
| CAPTCHA detection | Matched any `iframe[src*=recaptcha]`; eBay's working results page (541 links) reported "CAPTCHA present — needs a human" |
| `browser_upload` | Accepted paths that did not exist — "attached 1 file(s)", then 0% forever |
| `browser_screenshot` | Reported image dimensions while `region` takes CSS pixels, so coordinates read off the image landed elsewhere |
| `closeWorkstream` | Returned success having closed nothing, after a service-worker restart |
| Key chords | `Control+a` with nothing focused selected the whole document and reported success |

### Multi-agent safety

A call with no `tabId` resolved to the **globally active tab**. During testing
this navigated another session's Meta Business Suite tab away, mid-task. Tabs
were already claimed into per-session Chrome groups, so the ownership
information existed and simply was not consulted.

`resolveTab` now prefers the caller's own most-recently-used tab, falling back
to the active tab only when the session has none — which is right for a
session's first call, and for the side panel, where a human driving the panel
means the tab they are looking at.

That fix only holds if group membership is durable, and it was not. `groups.js`
kept a `name → groupId` map in service-worker memory, which MV3 discards after
~30s idle while the Chrome group survives. Three consequences, all fixed by
reading from Chrome instead:

- `assign()` created a **second** group with the same title, splitting the
  workstream
- `list()` reported **no workstreams at all** while they were plainly on screen
- `release` / `closeWorkstream` quietly did nothing and reported success

### Rich-text and navigation

**`newline: "soft"`** on `browser_input`. Rich editors open a paragraph on
Enter, which renders as a blank line — so in a Gmail composer `\n` gave one
break and `\n\n` gave three, and exactly one blank line between paragraphs was
unreachable. Verified by round-tripping a body through Gmail: the text came back
byte-for-byte, with clean `<br><br>`.

**bfcache error.** A click that navigated surfaced a raw Chrome string: *"The
page keeping the extension port is moved into back/forward cache, so the message
channel is closed."* `sendToFrame` already recovered from two other wordings of
the same condition; the bfcache wording fell through. All three now re-inject
and retry.

## Still open

1. **`browser_batch` has no `tabId` of its own** — every step must repeat it.
   This is the call shape a model reaches for first.
2. **A "page is settling" signal.** Clicks that register but do not navigate are
   indistinguishable from clicks that missed. Cheaper to build now: the tree
   cache already runs a MutationObserver, so the dirty flag is the signal.
3. **Untested: checkout/payment and OAuth sign-in.** OAuth in particular stresses
   cross-origin redirects and popups — exactly where frame routing and the
   port-death handling would be exercised.
4. **Infinite scroll is still unproven.** Both Reddit attempts hit a bot
   challenge, which the tool correctly refused to bypass. Pick a site that does
   not challenge rather than retrying Reddit.

## Calibration for whoever picks this up

The two sites hardened in the earlier pass (Gmail, Meta) produced **no** new bugs
this time. The two new site shapes (Hacker News, eBay) each produced several.

Expect that pattern: well-hardened against what it has been driven against, and
each genuinely new kind of site still costs about one bug. That is the honest
predictor, and it is why `docs/TESTING.md` matters more than the unit tests.

Known hard limits, unchanged: sites behind Cloudflare/Imperva/DataDome bot walls
(the tool refuses to bypass, by design), canvas and WebGL apps where the
accessibility tree returns nothing, and closed shadow roots.
